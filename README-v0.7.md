# 回声诊所 v0.7 · 诊疗、维修与康复后的聊天

Windows x86-64 / Godot 4.7.2 / 纯 2D 像素界面。双击同目录的 `EchoClinic.exe`，无需安装引擎。

这一版把主要循环落成了：**动手修设备 → 获得算力 T → 检查与治疗 → 病历归档 → 康复患者进入休息室**。文字负责人物、疑点和选择，轻量操作负责检查、发现与赚取资源。

## 怎样玩

界面最左边是休息室，中间是当前患者的诊疗聊天，右边是检查台。下方可以进维修站、看病历、查收支。F11 切换全屏，Esc 关闭弹窗，空格跳过当前演出/补全正在显示的对白。窗口采用最近邻缩放；1100×600 的整数倍显示最清晰，默认 1650×900 兼顾常见电脑屏幕。

1. 点击右侧“接诊检查 · 4T”便开始本轮检查，按钮已经标价。先点线路节点，看看每个程序在干什么。她写的名字不一定真实。
2. 录音检查用进度条拖动；附件检查用扫描条拖动。检查过程会出现撤回、改名和对照演出，不需要输入代码或大段阅读。
3. 可以直接在中间聊天追问矛盾。已实现的调查能由自然输入触发；自然语言提出的关键操作需明确确认。已标明动作的普通按钮不再重复弹确认；最终治疗和中途重开在右侧检查台签字。
4. 病历里的“本次接诊”会告诉你患者怎么了、现在的疑点、可以接着做的事。线索、历次结果和账本分别查看。
5. 想赚 T 时随时打开维修站。诊疗进度保留；工单做一半也能离开，稍后继续。

这仍是两幕悬疑 Demo。后续重开会按上一轮结果改变部分留言，但不是无限生成的新案件。灯芯是用来验证维修与康复循环的简短支线，不是第二份与回声等长的主线病例。

## 玩法与剧情如何连在一起

| 检查 | 玩家主要动作 | 故事作用 |
|---|---|---|
| 程序线路 | 点击节点、观察连线、确认切断 | 分清“停止监听”和“停止疼痛”是两件事，发现她的建议有所隐瞒 |
| 断裂录音 | 拖动时间轴、回到删除之前 | 操作时亲眼见到她撤回原话，找回的内容进入病历 |
| 可疑附件 | 拖动扫描条、查看收件人 | 扫描出的内容和“只是病历”的说法不符，是否转交留到之后决定 |
| 治疗方案 | 点击三张条件卡、比较她的复述、预演 | 她仍会争取有利条件；玩家决定能答应哪部分，最后单独确认 |
| 再次接诊 | 对照旧开场、查看留在医生电脑里的留言 | 已做的旧检查复用，调查新的异常，不再强迫重做第一套操作 |

台词改用日常语言，例如“不断改写她的程序”“清空记忆，恢复出厂设置”，术语只在设备标签和必要的证据中保留。病历中的事实必须来自已经完成的检查；AI 的自由发言不能凭空生成证据。

## Token 经济：目前已实现的规则

T 是虚构的诊所算力，不是 DeepSeek 实际计费的文本 token。用固定价格，避免玩家因为多写一句、模型多说几句而被额外惩罚。

| 收入或支出 | 数值 | 结算时机 |
|---|---:|---|
| 首次开诊补助 | +24T | 新版钱包首次建立，仅一次 |
| 完成一张维修工单 | +6T | 修复完成后手动结算，每单仅一次 |
| 回声首次康复补贴 | +6T | 首次保住她的记忆并完成治疗，仅一次；重复重开和其他康复结局不再领取 |
| 接诊检查 | −4T | 明确确认接诊后；涵盖这一轮的全部调查 |
| 治疗/标准化/完整迁出 | −8T | 明确确认并实际执行时；所有结束接诊的主要方案同价 |
| 有效在线聊天回复 | −1T | 中间诊疗和左侧休息室共用钱包；合格回复收到后才扣款 |
| 本地备用短回应 | 0T | 离线可用，不冒充完整的自然语言 AI |
| 剧情对白、调查意图、看证据、提示、预演、取消、重开 | 0T | 不按每句剧情收费 |

**钱从可操作的玩法来，主要花在接诊和自然聊天上。** 不是靠反复点对白领奖，也不按玩家选择的“好坏”多扣治疗费。病例第一次治愈的补贴只是教学期缓冲，长期收入来自维修。

### 维修站的三种工单

- **接通线路**：点击转动 3×3 接头，从入口接到出口。不同工单的走线模板与初始方向变化。
- **对齐节拍**：拖动三个推杆，对齐各自的目标刻线。没有限时和精确节奏判定。
- **清理坏块**：点击翻转当前格与上下左右，消除全部粉色坏块。题面由合法操作生成，保证有解。

工单免费领取，没有失败罚款，也没有每日次数限制。一次只持有一张，离开、重开剧情和退出后恢复的是同一张工单；结算后才生成下一张。提供免费“一步辅助”，让操作困难或卡题的人也能继续游戏。它是单机剧情资源，不做惩罚性的反作弊门槛。

灯芯负责这些设备，三种设备各修一次后恢复说话，进入休息室。重复修同一种也给工单报酬，但不会代替其他两类康复进度。

### 一段体验的预算

| 体验 | 算式 | 结束余额 |
|---|---|---:|
| 首轮康复，不额外闲聊 | 24 − 4 − 8 + 6 | 18T |
| 首轮康复，在线问 6 句 | 24 − 4 − 6 − 8 + 6 | 12T |
| 两轮治疗，不闲聊，首轮康复 | 24 − 12 + 6 − 12 | 6T |
| 再修一单，继续聊 6 句 | +6 − 6 | 收支相抵 |
| 从 0T 开始，再完成一轮接诊 | 两单 +12，检查 −4，治疗 −8 | 0T |
| 完成灯芯三种工单 | 3 × 6 | +18T，同时解锁灯芯 |

希望维修一单约 20–45 秒；这是设计目标，尚未经过外部玩家计时验证。对齐节拍通常会更快。三类工单先同价，避免为了高收益被迫刷某一种；如果试玩时大量时间花在赚钱而不是剧情，优先下调消耗或提高每单报酬，暂不增加新的货币、体力条和随机掉率。

### 避免卡死和错误扣款

- 余额为零也能进入维修站、读病历、查看线索、使用辅助；缺钱的操作保持原阶段。
- 扣款前会再检查可用余额。两个聊天窗口分别预留 1T，不能同时花掉最后一枚 T。
- 无效回复、越界回复、网络错误、超时、手动取消、过期回复都不扣游戏 T。服务端实际 API 请求仍可能已计费。
- 调查和关键确认由本地状态机处理；模型不能付款、发奖励、签字或改病历。
- 同一工单、同一次出院不能重复结算。重开不重发 24T，不清空账本，也不重置工单。
- 钱包、工单、病例、联系人和聊天放进同一个存档事务。中断请求不自动重发，也不恢复扣款预留。

## 康复后的自由聊天

休息室的下拉框切换**角色**：目前有回声和灯芯。回声在保留身份与新记忆的康复结局后加入；被重置、被冻结或去向不明不算康复。灯芯在三种设备各修好一次后加入。联系人随病历保留；重新接诊是恢复诊室中的患者，休息室保留已康复的记录，两边对话互不混写。

每位角色有自己的聊天记录、说话特点和简短背景。休息室不读取当前诊室里的新线索，没有推进剧情或执行治疗的通道；切换联系人会取消仍在等待的回复。当前没有亲密度、每日打卡或强制陪聊奖励，避免把自然聊天变成刷数值。

两个窗口共用 DeepSeek 配置。点击“AI 设置”，在游戏内填入自己的 API Key；可以调整模型名。密钥只保存在本次进程内，不写入存档或发布包。启用后，该窗口的近期对话和必要角色背景会发往 DeepSeek，实际费用由你的 DeepSeek 账户承担。游戏 T 不能兑换或支付 API 账单。

离线也能完成主线、维修、解锁角色和使用少量预写回应。想体验真正自然的自由聊天，需要接入 DeepSeek。角色提示、公开事实裁剪和输出检查一起限制越界；本地操作权限有硬边界，但不能保证生成文字百分之百不出戏。

## 病例与存档

- 本次接诊：症状、当前疑点、下一步操作方向。
- 线索卡片：只显示已发现的事实，重开保留。
- 历次结果：记录每轮结果、线索数量，列出康复联系人。
- 钱包账本：最近 80 笔收支，显示余额与聊天预留。

存档为 Godot 用户目录中的 `case-v7.json`；首次运行可接续 v0.6/v0.5/v0.4 病例，旧文件保持不变。旧版游戏内 T 不换算，新钱包统一从 24T 开始。旧病历已有的康复结局会解锁回声。不要同时运行两个 v0.7 实例操作同一存档。

## 后续扩展的约束

下一位主线患者应带来一种新的诊断动作、一个会影响治疗的隐瞒、一个康复后的聊天角色，而不是只增加文字长度。维修站可复用这些动作的简化版本，让玩家先熟悉手感，再在剧情里理解它的意义。

Steam 发行阶段仍需要决定：继续让玩家自备密钥，还是由服务端提供额度。若改为官方提供，服务端负责密钥、实际成本和限额，客户端不能内置公共密钥。本地 T 经济只调节游戏节奏，不能直接拿来承担真实 API 的无限成本。本版没有付费购买 T、联网账号或云存档。

## 验证与范围

测试报告随包附带，覆盖两幕剧情、全部主要结局、鼠标操作、低余额恢复、重复结算、双窗口预留、联系人隔离、存档往返以及 DeepSeek 格式的本地 HTTP 模拟请求。真实 DeepSeek 账号的响应质量和费用没有在本机验收；`live_api_verified` 为 `false`。

运行源码：打开 `project/project.godot`。测试夹具为 `tools/mock_deepseek_v7.py`；启动它后，以 `-- --self-test --ai-mock-url=http://127.0.0.1:18919 --capture-dir=绝对输出路径` 运行项目。`tools/package_v7.py` 需要源码和导出程序的两份测试报告都通过后才打包。
