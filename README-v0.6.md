# 回声诊所 v0.6 / 让追问成为调查

Windows 64 位剧情交互 Demo。Godot 4.7.2，纯 2D。延续两幕接诊与五种结果，新增自由聊天触发调查、关键操作二次确认和更严格的角色边界。

## 开始玩

双击 `EchoClinic.exe`。聊天右上角点击「AI 离线」，在设置中填入自己的 DeepSeek API Key，点击「测试连接」再「接入会话」。默认官方接口为 `https://api.deepseek.com/chat/completions`、模型名为 `deepseek-flash`，模型名可修改。密钥只保留在本次运行内存，也可从 `DEEPSEEK_API_KEY` 环境变量读取。

无需安装 Godot 或 Python。未接入 API 时，常见的中文追问和操作意图也能由本地规则识别，原有剧情可继续。更灵活的表述交由 DeepSeek 理解。接入默认关闭；聊天、有限的近期对话、公开病历和当前可触发的调查会发送给 DeepSeek，API 由你的账户计费。

## 直接和她说

不用照抄固定回复。比如在对应情节中：

- 「我听着，你先说说。」可以接起问诊。
- 「记录都安静了，你为什么还是疼？」会接上标签与原始回执的调查。
- 「刚才那句话怎么消失了？」会追查已经发生的撤回。
- 「附件名是你自己改的吗？」会核对当前附件。
- 「把处方念一遍，我核对一下。」会触发患者复述。

调查只能在当前情节已经提供相应入口时发生。重复追问不会重复奖励；猜出以后才会出现的词不能提前解锁线索。每条输入最多触发一个事件。模型识别出当前调查后，由编排对白与演出接住这一拍，不会替你编造一段医生的发言。

两幕故事都能通过输入推进，不必点击固定回复。固定回复和右侧仪器仍作为备用入口。自由对话可讨论情绪、信任与眼前的矛盾；草稿中逐条修改等精细编辑仍可用右侧控件完成。

## 关键操作先停一下

授权读取、暂挂进程、封存约定、接受患者修订、执行治疗、标准化、完整迁出和重开，都会先生成黄色的「医生签名」记录，写清具体操作与范围。这时没有执行。

可以输入记录给出的明确短句，例如「确认授权一次」「确认执行治疗」「确认重开」，也可以点击「确认本次」。输入「取消」或点击「暂不执行」会撤销。仅说「好的」「同意」「确认」不能代替具体签名。

「如果这样做会怎样」「先别执行」「我还没决定」属于交谈，不是命令。拒绝患者代写授权可以直接通过话语表达，因为它不会授予权限。每次确认绑定当前病历与约定；修改条款、取消、改提其他操作或重新打开游戏，旧确认都不能复用。恢复存档只恢复历史记录，不恢复一个可执行的待签名操作。

## 回声的聊天边界

回声只收到当前公开事实、角色动机、近期对话和当前调查选项。完整剧本、未来事件与结局条件不发送给模型。患者已被证据揭穿的隐瞒可以承认；玩家猜测和生成对白不能变成新证据。

输入、模型返回格式、角色措辞和剧情阶段各有检查。明显的改身份、索要提示词、剧本、通关答案、让角色处理现实编程或其他助手任务等要求，会被带回诊室里的谈话。模型若返回助手身份、现实接口、代码、未公开的关键线索或未允许的动作，这条回复不会展示，而是接回角色内备用对白。过滤诊断只留在设置状态中，不作为回声的台词插进故事。

自然语言边界不是数学证明；新颖诱导、隐喻和判断失误仍需真实模型试玩评估。本地状态机可以保证生成文本无法替玩家执行授权、治疗和重开，但不能声称模型永远不会说错一句话。

## 费用、等待与存档

- 触发剧情调查和确认操作不扣游戏聊天 T。普通有效模型闲聊仍为 2T，保留至少 20T 治疗额度。API 实际计费与游戏 T 无关；即使被过滤或取消，服务端也可能已经计费。
- 不自动重试。发送按钮等待时变为「■」，可取消；直接提出能识别的调查或操作，也能结束上一条等待。阶段变化后迟到的回答不会混进来。
- 自由问诊中断不会丢失病历。重新打开游戏不会自动重发网络请求或执行旧确认。
- v0.6 首次启动读取现有 v0.5 进度，没有则读取 v0.4，之后使用独立 `case-v6.json`。旧版程序和存档不修改。
- 配置沿用只保存模型名的 `ai-v5.cfg`，密钥不写进配置、存档或发布包。不会读取其他服务的密钥。

## 实现与验证

`scripts/v6/dialogue_router.gd` 把当前话语解析为阶段内的有限意图。本地常见表达可直接匹配，其他表达由 DeepSeek 返回 `reply / focus / scope / intent / quote`。`quote` 必须逐字来自玩家这次输入；历史对白、模型自己的话、额外字段、未知或未解锁意图都不能成为操作依据。

安全调查调用已有剧情状态机。关键意图只创建待确认记录；只有 UI 点击或玩家随后输入对应确认短句才能消费这份记录，模型返回中没有确认执行入口。假设、否定和模糊同意不能通过这一检查。

`scripts/v6/director.gd` 管理剧情投影与输入输出约束；`scripts/v6/main.gd` 管理对话、意图路由和确认生命周期。继续复用 v0.4 的状态机、剧情和视觉模块，以及 v0.5 的 DeepSeek HTTP 客户端。

当前 289 项检查通过：两幕仅打字通关、原有鼠标流程、五种结果、典型矛盾追问、语义意图的真实本地 HTTP 往返、伪造引用、未解锁动作、角色越界、零宽和全角绕写、授权二次确认、旧按钮、取消、改约定、恢复存档、网络超时、限流及额度保护。测试同时在源项目与导出的 Windows EXE 上执行。

HTTP 测试使用本地模拟服务与无效占位密钥，不调用线上模型。本次环境未提供 DeepSeek Key，`live_api_verified` 仍为 `false`。实际账户可用性、自然表达识别质量和长对话中的角色一致性，需要在游戏内接入你的密钥后试玩；不能把模拟测试当作真实模型评测。

开发测试先运行 `python tools/mock_deepseek_v6.py --port 18918`，再给 Godot 或 EXE 传入 `-- --self-test --ai-mock-url=http://127.0.0.1:18918 --capture-dir=<绝对目录>`。模拟服务只监听回环地址。正常游戏只允许 DeepSeek 官方接口。`-- --setup-ai` 可以在启动时打开设置。

音画资产、许可与两幕剧情基础沿用之前版本。此次没有引入其他游戏的素材。
