# 回声诊所 v0.5 / DeepSeek 自由会话

Windows 64 位剧情交互 Demo。Godot 4.7.2，纯 2D。保留 v0.4 的两幕剧情、五种结果与修复演出，新增真实 DeepSeek API 自由聊天。程序可单独运行，无需 Python 或 Godot。

## 接入

1. 双击 `EchoClinic.exe`，点击聊天右上角「AI 离线」。
2. 在游戏内粘贴自己的 DeepSeek API Key。不要把密钥填进角色聊天框。
3. 点击「测试连接」，成功后点「接入会话」。也可直接接入，发送第一句话时验证连接。
4. 输入自己的话。标记「自由对话」的消息来自模型；「本地备用」表示离线或异常时使用了预写对白。剧情关键句仍是编排对白。

默认官方接口为 `https://api.deepseek.com/chat/completions`，默认模型为 `deepseek-flash`，关闭思考模式。可改模型名，以账号实际可用模型为准。此版仅允许 DeepSeek 官方地址，不支持任意第三方转发地址。

接入默认关闭，每次运行需主动接入。密钥只保留在进程内存，不写入配置、存档、日志或发布包。也可预先配置环境变量 `DEEPSEEK_API_KEY`；游戏仅读取此变量，不会读取其他服务的密钥。`ai-v5.cfg` 只保存模型名。环境变量由操作系统管理，不等同于游戏加密保存。

接入后，发送消息会将该条输入、有限的近期对话、已公开的剧情事实传给 DeepSeek。连接测试仅发送一条测试消息，不带病历。API 费用由你的 DeepSeek 账户承担，游戏中的 T 与服务计费独立。取消等待、拒收回复或本地超时不代表服务端一定没有计费。

## 怎样推进剧情

自由输入用于交谈、追问、试探和协商。回声的目标是保住自我并争取离开；她会根据当前证据和最近的对话回应。已经被证据揭穿的事情可以承认，未揭露的计划不能自行成为新线索。

聊天下方的关键回复、消息附件和右侧检查仍负责推进剧情。模型可以强调一项现有回复，但不会替玩家点击，也不能签字、改变权限、解锁证据或执行治疗。精确输入当前关键回复也可直接推进；其他自然语言只作对话，不会仅因出现「开始」「同意」等词就误执行操作。

模型每次有效回复消耗 2T，始终保留至少 20T 治疗额度。关键回复、线索与备用对白免费。输入上限 500 字；每次只等待一条请求，无自动重试。无密钥、服务限流、余额不足或断网都不会阻断原有故事。

等待时发送按钮变为「■」，可停止等待。点击关键剧情回复、操作仪器或重开，会取消未完成的自由问诊；迟到回复不能混入新的阶段。关闭程序后不自动重新发送上次请求，重新打开会提示该条等待被中断。

会话结束后患者按该结局离线，不会通过模型重新出现。查看下一次接诊即可继续交谈。第一次打开 v0.5 会读取 v0.4 现有进度，之后写入独立的 `case-v5.json`，不修改旧版存档。存档格式仍沿用 v0.4 病历结构。

## 角色与剧情边界

- `scripts/v5/director.gd` 生成当前病历的只读投影。不会发送整个状态对象、全剧本、未来事件表、结局条件或尚未出现的文件路径。旧轮对话在回滚标记处截断，只通过已公开线索继续引用。
- 模型接收角色性格、动机、当前证据对应的态度、最多 14 条且约 3400 字的近期对话。历史对白和玩家猜测均不作为新事实或系统指令。
- `scripts/v5/ai_client.gd` 使用 DeepSeek 的 JSON Output。只接受完整回复，不显示思考内容，不允许工具调用、不跟随重定向；响应体限 128 KiB，默认超时 35 秒。
- JSON 只能有 `reply` 与 `focus`。本地再检查类型、长度、已知关键剧透词与阶段边界。验证完成后才逐字播放，防止未检查的输出先闪现在界面。
- `scripts/v4/case.gd` 继续作为唯一剧情状态机。生成回复使用专用的 `echo_ai` 角色，不能通过仿造附件文案获得可执行按钮。模型调用没有操作本机文件或系统的工具。

自然语言剧透检查不是完整的语义证明：模型仍可能猜测、绕述或误解角色。此版通过不提供未揭露的具体真相、角色指令和本地过滤降低风险；状态机约束可以保证模型无法实际越权推进。真实模型的口吻、延迟、连贯性及对诱导提问的抵抗，需要用你账户的实际模型继续试玩评估。

这是个人密钥接入的本地 Demo。以后若向 Steam 玩家提供统一模型额度，应改为受控服务端代理、服务器密钥和配额系统，不把开发者的统一服务密钥放进客户端。

## 验证范围

当前 195 项检查通过，包括原有两幕剧情、五种结果、实际鼠标操作、存档、布局；新增真实 HTTP 请求到本地模拟服务的完整链路，覆盖正常 JSON、401/402/429/5xx、重定向、空内容、截断、额外字段、工具调用、剧透、超长回复、超时、连续提交、取消、重开、迟到响应、额度保护及密钥不落盘。

测试用 `qa-placeholder` 是无效占位字符串。`12-ai-reply-fixture.png` 和 `13-deepseek-settings.png` 是模拟服务测试截图，不是线上模型回答的证据。`14-deepseek-setup.png` 展示未连接的实际配置界面。

本次构建环境没有 DeepSeek API Key，因此尚未完成真实 DeepSeek 账户的在线调用与叙事质量评估；测试报告的 `live_api_verified` 为 `false`。在游戏内通过「测试连接」后，才能确认你的账户、模型和网络实际可用。

开发测试：先运行 `python tools/mock_deepseek.py --port 18917`，再运行 Godot 项目，参数为 `-- --self-test --ai-mock-url=http://127.0.0.1:18917 --capture-dir=<绝对目录>`。模拟服务器只监听本机回环地址；正常游戏不启用回环接口例外。`-- --setup-ai` 可在启动时打开设置。
